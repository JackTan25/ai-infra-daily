### [1] [Cambium: Participant-Built Commitment Roots for Shared Digital Infrastructure](https://arxiv.org/abs/2610.30409)
*Mansoor "Manny" Ahmed,Dann Toliver,Ekaterina Pavlova*

Main category: cs.DC

TL;DR: Cambium 是一个许可制 P2P 承诺服务，通过固定大小委员会认证输入 + 递归倍增合并（disjoint groups 重算所有中间值）来去中心化地共同构建每周期承诺根，避免单一运营者或全链共识；每节点每周期 O(c log(n/c)) 消息、存 O(log(n/c)) 证明与 O(n) 成员名册；Go 原型在 AWS 上 c=4、8–256 节点、含模拟 straggler，周期 12–148 ms，证明验证 <1.5 ms，呈对数增长；安全性上冲突证书可定位签名者，双根同时 final 需 ≥1/3 Byzantine 节点（失败概率随委员会数指数小）。


<details>
  <summary>Details</summary>
Motivation: 现有承诺服务（时间戳、透明日志、来源登记）要么依赖单一运营者，运营者即可决定根包含哪些输入；要么用区块链以全网对每次写入达成共识为代价换取去运营者化，吞吐与延迟成本过高。目标是：无人能单方面决定承诺根的内容，同时不需要全网共识、并把根构建与验证成本分摊到全体参与者。

Method: 许可制（permissioned）P2P 服务。每周期由参与者共同构建承诺根：(1) 固定大小委员会 c 负责认证（certify）输入并签名；(2) 递归倍增合并（recursive-doubling merge）：不相交的组对每个中间值独立重算，从而把根构建分摊到所有节点并可交叉校验；(3) 冲突证书（conflicting certificates）暴露签名者，形成问责；(4) 证明将签名输入绑定到根，每节点仅需保存自己的 O(log(n/c)) 证明 + O(n) 成员名册。实现为 Go 原型，部署于 AWS，c=4，8–256 节点，注入模拟 straggler 测量周期延迟与证明验证时延。

Result: 每成功周期的每节点消息复杂度 O(c log(n/c))（c 为委员会大小），每节点每周期存储 O(log(n/c)) 证明加 O(n) 名册。AWS 上 c=4、8–256 节点、含模拟 straggler 时周期耗时 12–148 ms，证明验证 <1.5 ms，实测成本随规模呈对数增长。安全性：冲突证书可识别签名者；证明将签名输入绑定至其根；两个冲突根同时 final 需至少 1/3 节点 Byzantine，且该失败概率在委员会数量上指数小。

Conclusion: 论文给出了可部署的“去运营者化”承诺服务设计：以委员会 + 递归倍增合并替代单运营者信任与全链共识，代价是每节点对数级消息与存储，换来毫秒级周期和亚毫秒级证明验证及可问责的 Byzantine 容错阈值。作者同时指出实际部署社区必须自行回答成员准入（membership）、证明可用性（proof availability）与排除（exclusion）三类治理/系统问题——这些是可用性与抗审查性的关键工程约束。

Abstract: Commitment services, such as timestamping, transparency logs and provenance registries, let a party prove that it bound itself to a record without publishing the record. Today an operator runs them, or a blockchain replaces the operator at the cost of network-wide agreement on every write. We present Cambium, a permissioned peer-to-peer service in which participants build each cycle's commitment root together, so that no single party decides which inputs the root includes. Fixed-size committees certify inputs and use a recursive-doubling merge, in which disjoint groups recompute every intermediate value, to spread root construction across all participants. A successful cycle costs each node $O(c\log(n/c))$ messages for committee size $c$, and each node stores its own $O(\log(n/c))$ proof per cycle, along with the $O(n)$ membership roster. A Go prototype on AWS with $c=4$, 8-256 nodes and simulated stragglers completes cycles in 12-148 ms and verifies proofs in under 1.5 ms, and demonstrates logarithmic growth. We show that conflicting certificates identify their signers, that a proof binds a signed input to its root, and that two conflicting roots both become final only if at least a third of the nodes are Byzantine, except with probability exponentially small in the number of committees. We also set out the membership, proof-availability and exclusion questions a community deploying Cambium must answer.

### [2] [Repair Changes Which Layers to Remove: Exact Optima for Depth Pruning of Language Models](https://arxiv.org/abs/2610.30552)
*Jianchang Su,Dawei Xiang,Yifan Zhang,Wei Zhang*

Main category: cs.DC

TL;DR: 论文系统性地穷举了深度剪枝中"删除哪些层"的所有可能组合（约5.3万个剪枝模型、四个模型族、含/不含线性修复），发现最优删除层集合依赖于所用的修复方式：线性修复会吸收相邻层间的交互作用，使最优点从"分散布局"变为"连续块"。据此提出在将要应用的修复下选择层，贪心搜索（成本约一个 SLEB）在五个最大27B模型上较 ReplaceMe 降低困惑度20%–66%，同数据下任务准确率最高提升25个百分点；并用损失的二阶展开得到只需对完整模型一次前向+一次反向即可选出修复后连续块的评分。


<details>
  <summary>Details</summary>
Motivation: 深度剪枝（整层删除）是加速大模型推理的直接手段，近期方法用免训练的线性映射修复被删层以恢复质量。但"删哪些层"仍由启发式评分决定，该评分与真实最优解的距离未知，导致剪枝配置次优。作者要量化这一差距，并厘清层选择与修复手段之间的耦合关系。

Method: 1) 对层组的每个子集做精确穷举评估（约53,000个剪枝模型，覆盖四个模型族，分别在无修复与有线性修复两种设定下）。2) 基于穷举结果分析修复对最优层布局的影响，指出修复会耦合邻近层、把最优解从离散分布推向连续块，并统计无修复选层相对"修复后最优"的偏差（最高189%）。3) 提出"在选择层时就纳入将应用的修复"的原则。4) 实现贪心搜索选层（搜索成本约一个 SLEB），并给出带任务目标的变体。5) 用损失的二阶展开推导评分函数，实现对完整模型仅一次前向+一次反向即可选出修复后的连续块。

Result: 精确穷举显示最优删除集合强烈依赖修复方式，忽略修复的选层方法相对修复后最优最多差189%。在修复下做贪心选层，于五个最大27B参数的模型上相对 ReplaceMe 困惑度降低20%–66%；在相同数据预算下引入任务目标可提升准确率最多25个点。二阶展开评分能以一次前向+一次反向的代价选出修复后的连续块。

Conclusion: 层选择不应与修复解耦：剪枝决策必须在目标修复算子（如线性修复）下评估，否则启发式选层会系统性偏离真实最优。在此原则下，廉价贪心搜索与二阶损失评分即可获得显著的质量收益，把深度剪枝的调优问题从"猜测式启发式"转为"修复感知的可验证选择"。

Abstract: Depth pruning removes entire transformer layers to make large language models faster, and recent methods recover quality by replacing the removed layers with a training-free linear map. Which layers to remove, however, is chosen with heuristic scores whose distance from the best choice is unknown. We evaluate every subset of layer groups exactly (about 53,000 pruned models across four families, with and without repair) and find that the best layers to remove depend on the repair: linear repair absorbs the interaction among nearby layers and turns the optimum from a split layout into a contiguous block, so methods that choose layers without the repair miss the repaired optimum by up to 189%. We therefore select layers under the repair that will be applied. A greedy search at the cost of SLEB lowers perplexity by 20% to 66% relative to ReplaceMe on five models up to 27B parameters, and with a task objective it is up to 25 points more accurate given the same data. A second-order expansion of the loss yields a score that selects the repaired block from one forward and one backward pass of the intact model.

<details>
  <summary>Details</summary>

Conclusion: 论文的核心贡献是把 GDS 的控制面从内核态与闭源引擎中解耦出来，用"用户态 NVMe 命令管理 + 极薄特权内核模块 + 队列分区 + 弱化顺序语义"的组合，在保持 P2P DMA 零拷贝优势的同时消除了 per-I/O 内核陷出与过度排序带来的开销。工程意义在于：小请求（KV block 级）高并发 I/O 才是 AI 推理存储路径的真实瓶颈，而这类负载需要的是批级语义与多队列隔离而非全序保证；同时开源与跨厂商 API 使存储路径可观测、可调度，可直接作为 vLLM/LMCache/TensorRT-LLM 的 KV-cache 分层后端，并为后续工作（异步/copy engine 集成、CUDA stream 深度耦合、CXL 与多租户 QoS）留出接口。

NVIDIA GPU Direct Storage (GDS) enables direct SSD-GPU transfers via PCIe peer-to-peer DMA, eliminating host staging.
