### [1] [DexAttention: Distributed Sparse Attention through Rapid Online Planning and Persistent GPU Execution](https://arxiv.org/abs/2611.23512)
*Sirui Chen,Xuehai Qian*

Main category: cs.DC

TL;DR: DexAttention 是一个面向分布式训练的稀疏注意力系统，将"在线规划"与"持久化执行"协同设计：用 GPU 加速的拓扑感知聚类完成 mask-aware 的任务分配（assigner），用轻量贪心调度器对粗粒度通信/计算算子排序，再由每张 GPU 上的 persistent kernel 负责细粒度依赖与任务派发，从而把同步细节移出规划阶段、避免重复 kernel launch。在 4 节点 16 GPU 集群上，11 组配置几何平均端到端训练加速 1.39×；动态视频注意力较 Ring Attention 加速 2.11–2.37×（含规划开销）。


<details>
  <summary>Details</summary>
Motivation: 稀疏注意力虽然降低了计算量，但分布式执行时仍会传输多余数据，并承担大量逐操作开销（kernel launch、同步等）。Mask-aware 的任务分配与调度能降低这些成本，但对动态 mask 而言，重规划本身的代价必须小于它节省的执行时间——即"规划开销 vs. 收益"的权衡是核心难点。

Method: 1) Assigner：GPU 加速、拓扑感知的聚类算法，同时平衡计算负载并减少通信量；2) 轻量贪心 scheduler：对粗粒度的通信与计算算子进行排序；3) 每 GPU 上的 persistent kernel：负责细粒度依赖强制与 ready task 派发，取代反复 launch 注意力 kernel；4) 规划层与执行层职责分离，规划只处理粗粒度抽象，细粒度同步留在运行时；5) 框架支持 per-head 的静态与动态 mask，并适配多种注意力计算 kernel。

Result: 在 4 节点 16 GPU 集群上：11 组配置相对最强适用基线的端到端训练几何平均加速 1.39×；针对动态视频注意力，相比 Ring Attention 达到 2.11–2.37× 加速，且该数字已包含规划开销。

Conclusion: 论文的关键洞见是：分布式稀疏注意力的瓶颈从"算力节省"转移到"数据搬运与按操作开销"，因此必须让规划足够便宜、执行足够持久。通过 co-design 廉价的在线聚类分配与 persistent kernel 执行，DexAttention 使 mask-aware 调度对动态 mask 也可负担，可在不改变现有注意力 kernel 的前提下获得稳定端到端收益。

Abstract: Sparse attention reduces computation, but distributed execution may still transfer unnecessary data and incur substantial per-operation overhead. Mask-aware assignment and scheduling can reduce these costs, but replanning for dynamic masks must be cheaper than the execution time it saves. We present DexAttention, a distributed sparse attention system that co-designs fast online planning with persistent execution. Its assigner uses GPU-accelerated, topology-aware clustering to balance computational load and reduce communication. A lightweight greedy scheduler orders coarse communication and computation operations, while a persistent kernel on each GPU enforces fine-grained dependencies and dispatches ready tasks. This division keeps detailed synchronization out of planning while enabling overlap without repeated attention launches. The framework supports static and dynamic per-head masks across multiple attention compute kernels. On a four-node, 16-GPU cluster, DexAttention achieves a $1.39\times$ geometric-mean end-to-end training speedup over the fastest applicable baseline across 11 configurations. For dynamic video attention, it achieves $2.11$--$2.37\times$ speedups over Ring Attention including planning.

<details>
  <summary>Details</summary>
Motivation: SAC 系统（Corfu、NOPaxos、LazyLog、SwitchBFT）十多年来一直靠纸笔证明或协议层有界模型检验来论证正确性，缺少对真实实现、尤其对代码级线性化性质的机器验证。直接做验证看似容易：定序器决定全序，可把线性化点放在定序器处（prophecy variable 的经典用法）。但该线性化点不具持久性——定序器排序发生在任何副本提交之前，崩溃触发的 view change 可能丢弃该请求，使先前"已确定"的顺序与依赖它的证明失效。这正是验证 SAC 时真正的技术障碍，而非排序本身。

Conclusion: 该工作把"定序器辅助协调"从依赖非形式化论证的工程实践，推进到代码级、机器检查正确性的阶段，并给出了可接受的性能代价（≤17%）。工程意义在于：第一，跨视图持久性是 SAC 类系统（含共享日志、共识 offload、定序器集中排序）的核心正确性风险点，Stephen 的证明技术为此提供了可复用的方法论；第二，17% 的区间意味着验证实现可用于生产路径或关键组件，而不只是参考模型；第三，验证过程本身具备缺陷发现能力，说明形式化验证可作为定序器类数据面/控制面协议的审计手段。局限在于验证成本（证明工程量、框架与语言依赖）尚未量化，且跨视图开销的具体来源（日志、额外状态交换还是证明驱动的实现约束）未在摘要中区分，这直接决定其在低延迟推理服务与高吞吐训练数据通路中的可部署性。

Abstract: Many distributed systems achieve high performance by relying on dedicated sequencers to order requests, leaving replicas to commit them in that order. Despite more than a decade of such sequencer-aided coordination (SAC) systems, from Corfu and NOPaxos to LazyLog and SwitchBFT, their correctness has been argued only with pen-and-paper proofs or bounded model checking at the protocol level.

The sequencer seems to make this easy: it decides the order of all requests, so the proof can place each request's linearization point at the sequencer using a well-known technique, prophecy variables. Yet a linearization point placed at the sequencer is not durable, because the sequencer orders a request before any replica commits it. Crashes and other rare events may trigger a view change that discards the request, nullifying the earlier decision and the proof that rests on it.

(1) We develop cross-view prophecy peek, which lets the proof follow a request across view changes until it is either committed or permanently discarded. (2) Our verification uncovered bugs in existing SAC implementations, including one that can lose committed requests. We fix them and prove the fixes correct. (3) We apply Stephen to NOPaxos, Corfu and LazyLog. We build verified implementations with machine-checked proofs of linearizability. They perform within 17% of their open-source, unverified counterparts. The verified implementations and proofs will be open-sourced.

Method: 核心思路：将 reverse offload 从 fallback 提升为 first-class 通信路径，并作为可编程接口暴露给用户，使用户能定义 workload-specific 的通信操作（即把通信控制逻辑卸载到 host proxy 上执行，GPU 侧只做轻量触发/分工）。

We further propose exposing reverse offload as a programming interface that lets users define workload-specific communication operations.

We address practical challenges of scaling reverse offload, including contention on shared queues, polling overhead, and load imbalance across proxies. KIWI-P2P, a SHMEM-like library built on KIWI, outperforms state-of-the-art GDA implementations in both latency and bandwidth. More importantly, KIWI-EP redesigns low-latency mixture-of-experts dispatch and combine kernels around workload-defined operations, lowering expert-parallel communication latency by up to 2.3x over the best existing backend on AMD GPUs and time per output token in vLLM by up to 29%. The source code of KIWI is available at https://github.com/AMDResearch/kiwi.

### [5] [Locality-Aware Scheduling for Stream Processing Applications in Serverless Environments](https://arxiv.org/abs/2611.23879)

Main category: cs.DC

<details>
  <summary>Details</summary>
Motivation: 有状态 FaaS 平台把状态服务器部署在 worker 上，与计算共置以降低状态访问延迟。但现有 SOTA 采用 worker 级分布式调度，将链式请求直接路由到目标 worker 以避开中心化调度器、减少网络开销时，存在一个隐含约束：同一算子的状态与执行必须落在同一 worker。这导致流水线中"算子 A → 算子 B"的跨算子调用大多必须跨 worker 迁移，反而引入额外延迟与 I/O 开销。核心矛盾是：状态共置（state-affinity）与调用链本地性（chain-locality）在单一放置维度下无法同时满足。
