### [2] [One-Sided Expert-Parallel All-to-All for Mixture-of-Experts Inference over NVLink](https://arxiv.org/abs/2611.13188)

  <summary>Details</summary>

We expose NVLinkOneSided through a modular interface, so that it is agnostic to the activation quantization format, decoupled from the MoE compute backend and easy to integrate into inference frameworks.

### [4] [Scaling Shapley Energy Attribution to Large LLM Batches](https://arxiv.org/abs/2611.13802)
*Qi Luo,Ziwen Wang,Kunlin Li,Changxi Liu,Yun Chen*

Main category: cs.DC

TL;DR: StepSplit 提出面向批处理 LLM 推理服务的公平能耗归因方法：基于"每步能耗 = 共享能耗（读权重）+ 请求特定能耗"的分解，推导出 Shapley 值的闭式解，仅需一次 2.5–17.8 分钟的微基准标定，即可在静态/连续批处理下以 0.4–6.4% 的 L1 误差逼近真实 Shapley 值，而按 token 比例分摊的误差为 13.4–71.7%。


<details>
  <summary>Details</summary>
Motivation: LLM 服务需要按请求做计费与成本归因，能耗是关键指标。但 serving engine 将多请求打包成 batch，GPU 只上报聚合功耗（如 NVML 的整卡/整 GPU 能量计数），无法直接归属到单请求；业界常用的"按 token 数比例分摊"忽略了不同请求在 prefill/decode、序列长度、KV cache 占用和算子效率上的差异，导致显著低估或高估。理论上 Shapley 值是公平归因的公理化解，但其精确计算需对 N 个请求做 2^N−1 次 GPU 运行（含空集），在大 batch 下完全不可行。

Method: 1) 观测与建模：跨 GPU 代际发现单次推理 step（一次 forward）的能耗可分解为共享能耗（主要由读取模型权重决定，近似与 batch 组成无关）与请求特定能耗之和。
2) 闭式 Shapley 解：在该可加结构假设下，将 Shapley 值化简为"请求自身能耗 + 其参与的每个 step 的共享能耗均摊份额"，避免指数级枚举。
3) 标定：用 2.5–17.8 分钟的微基准，对给定模型 + GPU 配置一次性地拟合两部分能耗模型参数。
4) 静态批处理：直接对 scheduler log 做单遍扫描套用闭式解。
5) 连续批处理：移除某请求会改变剩余请求的组批方式（batch 组成与 step 数变化），因此引入一个修正项，通过在 CPU 上重放调度器（replay）计算该组合效应，避免额外 GPU 运行。
6) 评测：以 529,513 次 GPU 运行测得的经验 Shapley 值作为 ground truth 对照。

Abstract: LLM services have become essential infrastructure for applications such as chat assistants and coding agents. Service providers need to attribute resource consumption to individual requests for purposes such as billing. Among these resources, energy is a key metric for assessing the cost of serving each request. However, serving engines batch requests together, and GPUs report only aggregate energy consumption. Providers typically estimate each request's share in proportion to its token consumption, but this approach can produce substantially unfair estimates. The Shapley value provides a principled solution to fair energy allocation, but computing it directly requires $2^N-1$ GPU runs for $N$ requests, which is infeasible for large batches.
  To address this problem, we propose StepSplit. Across GPU generations, we observe that the energy consumed by each inference step, a forward pass over a batch, consists of a shared energy, largely due to reading model weights, and a request-specific energy. Under continuous batching with 8-128 requests, the corresponding errors are 0.5-6.4% and 20.6-71.7%.

### [5] [Decode Token Parallelism: Memory-Efficient Distributed Attention Parallelism for Scalable LLM Decoding](https://arxiv.org/abs/2611.13293)

  <summary>Details</summary>

Abstract: Serving large language models at high concurrency with long contexts requires KV-cache capacity and attention bandwidth that grow with the decode pool. Existing parallelization strategies trade one against the other: data parallelism replicates model weights, limiting KV capacity; tensor parallelism stops scaling attention at the model's KV-head count and pushes dense collectives across nodes; and decode context parallelism (DCP) recovers capacity by sharding the sequence but adds cross-node aggregation of partial attention results. We present Decode Token Parallelism (TKNP), a decode-pool architecture that decouples weight placement from attention ownership. TKNP distributes a single model copy across nodes in balanced layer blocks. The active node holding a block executes its projections and MLP for the full batch using intra-node tensor parallelism, while every node computes attention for its own requests against locally resident KV cache. Implemented in vLLM and evaluated on Llama 3.1 405B and Nemotron-4 340B on up to 64 H100 GPUs, TKNP improves completion throughput for long-context, high-concurrency workloads by up to 1.7$\times$ over DCP and by up to 2.06$\times$ over data parallelism at matched GPU count.

Conclusion: 主要贡献是把"云站点关键度"作为一等的放置约束引入RAN功能编排，将鲁棒性从被动冗余转为主动的故障域设计，为解耦移动网络的规划与故障域感知调度提供了可量化的优化框架。工程含义：对运营商，可在云化RAN规划阶段生成抗毁放置与"关键度SLO"；对系统侧，其思路（依赖度+关键度约束的放置）可迁移到推理服务、微服务与算子图在多集群/多可用区的部署决策，但需注意其关注静态放置、评估以RU存活数为主，缺乏对恢复时延、重调度开销与真实流量负载下的动态失效传播的刻画。

Abstract: The disaggregation of base stations into radio access network (RAN) functions introduces new vulnerabilities to mobile networks, as disruptions in cloud locations can interrupt multiple RAN functions and trigger cascading failures, leading to widespread outages. In this paper, we propose a criticality-aware RAN function placement solution to improve the robustness of disaggregated mobile networks against random failures and targeted attacks. Our solution optimizes the placement of centralized units (CUs) and distributed units (DUs) across cloud locations to reduce functional dependencies and limit the criticality of cloud locations, while preserving the cost benefits of RAN function centralization. We formulate the placement as an optimization model that jointly minimizes functional dependency and placement cost, subject to criticality constraints, as well as computing and transport requirements. We numerically evaluated our approach on a real-world mobile network topology across multiple disruption scenarios and demonstrated that our solution improves robustness, yielding up to 75% more operational radio units (RUs) after disruptions than existing approaches.
