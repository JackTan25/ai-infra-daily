### [1] [Reconstructing Fine-grained Memory Reuse Structure in GPU Kernels](https://arxiv.org/abs/2611.14741)
*Yanbo Zhao,Yueming Hao,Zecheng Li,Mao Lin,Shuyin Jiao,Keren Zhou,Xu Liu,Jiajia Li*

Main category: cs.DC

TL;DR: cuVein 提出 Topological Distance 与 PCDepGraph 两种抽象，直接从优化后的 GPU 二进制重建内核级内存复用结构，在无采样、开销低于10x的前提下指导消除最多90.18%的内存指令并实现最高2.84x内核加速。


<details>
  <summary>Details</summary>
Motivation: GPU数据搬运优化需要知道哪些指令访问同一份数据、在哪个执行作用域（thread/warp/block/grid）发生复用。现有profiler只能把访存行为归因到单条指令，却不暴露指令间的复用关系；而别名、动态索引和运行时参数使静态分析一般无法建立这些关系。cycle级模拟可以重建关系但开销对生产负载不可接受。

Method: 引入两种抽象：(1) Topological Distance——为每条动态访存打标签，标记包含其最近一次复用的最小执行作用域（thread/warp/block/grid）；(2) PCDepGraph——把这些标签组织成PC级图，刻画内核的内存复用结构。表示定义在逻辑执行作用域而非瞬态硬件状态上，因此跨运行与跨GPU目标稳定，并直接指出候选优化机制必须覆盖的共享作用域。工具cuVein直接从优化后的二进制重建PCDepGraph，无需采样。

Result: 开销通常低于10x；在NVIDIA RTX 4090与H100上的HPC与AI负载中，由PCDepGraph引导的优化最多消除90.18%的访存指令，内核加速最高2.84x；复用作用域分布在两平台上保持一致。

Conclusion: 跨平台的复用作用域分布一致性支持该表示刻画的是程序结构而非瞬态硬件行为。其工程意义在于：以可接受的开销提供可移植、可复现的指令级内存复用关系，直接为寄存器/共享内存/L1/分布式共享内存等不同层级的复用消除提供决策依据，替代昂贵的cycle级模拟。

Abstract: Optimizing GPU data movement requires knowing which instructions access the same data and across which execution scopes reuse occurs. Existing profilers can attribute memory behavior to individual instructions but do not expose the reuse relations among them, while aliasing, dynamic indexing, and runtime parameters prevent static analysis from establishing these relations in general. Cycle-level simulation can reconstruct such relations, but at costs prohibitive for production workloads. We introduce two abstractions for representing this structure: Topological Distance, which labels each dynamic memory access with the smallest execution scope (thread, warp, block, or grid) containing its most recent reuse, and PCDepGraph, which organizes these labels into a PC-level graph of the kernel's memory reuse structure. Defined over logical execution scopes rather than transient hardware state, the representation remains stable across runs and GPU targets while directly indicating the sharing scope that candidate optimization mechanisms must cover. Our tool, cuVein, reconstructs PCDepGraph directly from optimized binaries, without sampling, at generally under 10x overhead. Across HPC and AI workloads on NVIDIA RTX 4090 and H100, optimizations guided by PCDepGraph eliminate up to 90.18% of memory instructions and yield up to 2.84x kernel speedup; reuse-scope distributions remain consistent across platforms, supporting that the representation captures program structure rather than transient hardware behavior.

### [2] [SubGPU Pipelining: Intra-GPU Fine-Grained Spatial Parallelism for LLM Inference](https://arxiv.org/abs/2611.14904)
*Muralidhar Andoorveedu,Marius Juston,Tingkai Liu,Sanjay Patel*

Main category: cs.DC

TL;DR: 论文提出 SubGPU Pipelining：一种 GPU 内部的细粒度空间执行模型，把算子图切分为有序连续段并绑定到由不相交 SM 池支撑的空间 stage，微批次沿流水线流动以重叠 decode 阶段的 bursty 访存与计算资源使用；并用共享资源解析模拟器联合优化图切分、段-stage 绑定、每 stage SM 分配与 microbatch 大小，再用单卡 B200 配合 CUDA Green Contexts 与 TensorRT-LLM kernel 做硅验证。


<details>
  <summary>Details</summary>
Motivation: LLM decode 由大量短小、以访存为瓶颈的 kernel 主导，对 SM 计算资源与 HBM 带宽的使用高度突发化：单 kernel 内难以同时吃满算力与带宽，kernel 间存在下发与同步空隙，导致 per-user 延迟与 per-GPU 吞吐无法同时最优。传统的时序（temporal）执行把整张图顺序跑完，无法利用不同阶段对资源需求的差异做空间重叠。

Method: (1) 将算子图切成有序连续 segment，绑定到物理隔离的 SM 池（spatial stage），microbatch 流水穿过各 stage，实现段间空间并行、段内仍按时序执行；(2) 建立考虑共享资源竞争（带宽、L2/cache 状态、SM 占用）的解析模拟器，在 SubGPU pipeline 结构与 batch size 空间内搜索 per-user / per-GPU 吞吐 Pareto 前沿；(3) 硅上验证：单张 B200 模拟 32-GPU B200 部署（GPT-OSS 120B，global batch 2048），用 CUDA Green Contexts 做 SM 分区、TensorRT-LLM kernel 执行，选取一个两 stage 配置观测实际收益。

Result: 模拟层面：在等 per-GPU 吞吐下，SubGPU 前沿的 per-user 吞吐最高为 temporal 执行的 2.2x；在等 per-user 吞吐下，per-GPU 吞吐最高提升 1.9x。硅上实测（两 stage、单卡模拟 32 卡、batch 2048）：DRAM 读写平均带宽利用率从 71.8% 提升到 83.6% peak，36 层 decoder iteration 时间下降 10.33%。

Abstract: Large language model (LLM) decode is dominated by short, predominantly memory-bound kernels that make bursty use of on-chip execution resources and memory bandwidth. This paper introduces SubGPU Pipelining, a fine-grained, intra-GPU spatial execution model that cuts an operator graph into ordered contiguous segments, binds those segments to spatial stages backed by disjoint streaming-multiprocessor (SM) pools, and streams microbatches through the resulting schedule. Selecting the graph cuts, segment-to-stage binding, per-stage SM allocation, and microbatch size is a coupled optimization problem: each choice changes the overlap pattern, shared-resource contention, cache state, and execution times of the others.

The analytical shared-resource simulator searches across SubGPU pipeline structures and batch sizes to map the per-user/per-GPU throughput Pareto frontier. At matched per-GPU throughput, the modeled SubGPU frontier provides up to 2.2x higher per-user throughput than temporal execution, and at matched per-user throughput it provides up to 1.9x higher per-GPU throughput. To test physical feasibility and further validate the simulation results, silicon experiments are performed, using one B200 GPU to emulate a 32-GPU B200 deployment. The experiment evaluates one selected two-stage pipeline configuration at global batch 2,048 using CUDA Green Contexts and TensorRT-LLM kernels.
