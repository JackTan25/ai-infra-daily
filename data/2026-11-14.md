### [1] [Reconstructing Fine-grained Memory Reuse Structure in GPU Kernels](https://arxiv.org/abs/2611.14741)
*Yanbo Zhao,Yueming Hao,Zecheng Li,Mao Lin,Shuyin Jiao,Keren Zhou,Xu Liu,Jiajia Li*

Main category: cs.DC

TL;DR: 提出 Topological Distance 与 PCDepGraph 两种抽象，直接从优化后二进制重建 GPU 内存复用结构（无需采样），工具 cuVein 开销通常 <10x；据此引导的优化最多消除 90.18% 内存指令、获得最高 2.84x kernel 加速，且复用作用域分布在 RTX 4090 与 H100 上保持一致。


<details>
  <summary>Details</summary>
Motivation: GPU 数据搬运优化的前提是知道哪些指令访问同一份数据、在哪个执行作用域内发生复用。现有 profiler 只能把访存行为归因到单条指令，不暴露指令间的复用关系；而别名、动态索引与运行时参数使得静态分析无法一般性地建立这些关系；周期级模拟虽可重建，但开销无法承受生产负载。

Method: 提出两种表示抽象：(1) Topological Distance——为每条动态访存标注包含其最近一次复用的最小逻辑执行作用域（thread / warp / block / grid）；(2) PCDepGraph——把这些标签组织成 kernel 内存复用结构的 PC 级图。表示定义在逻辑执行作用域而非瞬态硬件状态之上，因此跨运行、跨 GPU 目标稳定。工具 cuVein 在优化后二进制上无采样地重建 PCDepGraph。

Result: 重建开销通常在 10x 以内。在 NVIDIA RTX 4090 与 H100 上的 HPC 与 AI 负载中，由 PCDepGraph 引导的优化最多消除 90.18% 的内存指令，实现最高 2.84x 的 kernel 加速；复用作用域分布在两个平台上保持一致，支持该表示刻画的是程序结构而非瞬态硬件行为。

Conclusion: 将"跨指令的内存复用关系"提升为一等、可静态持有且跨平台稳定的程序属性，是在不引入模拟器级开销的前提下做出数据搬运决策的可行路径。

Abstract: Optimizing GPU data movement requires knowing which instructions access the same data and across which execution scopes reuse occurs. Existing profilers can attribute memory behavior to individual instructions but do not expose the reuse relations among them, while aliasing, dynamic indexing, and runtime parameters prevent static analysis from establishing these relations in general. Cycle-level simulation can reconstruct such relations, but at costs prohibitive for production workloads. We introduce two abstractions for representing this structure: Topological Distance, which labels each dynamic memory access with the smallest execution scope (thread, warp, block, or grid) containing its most recent reuse, and PCDepGraph, which organizes these labels into a PC-level graph of the kernel's memory reuse structure. Defined over logical execution scopes rather than transient hardware state, the representation remains stable across runs and GPU targets while directly indicating the sharing scope that candidate optimization mechanisms must cover. Our tool, cuVein, reconstructs PCDepGraph directly from optimized binaries, without sampling, at generally under 10x overhead. Across HPC and AI workloads on NVIDIA RTX 4090 and H100, optimizations guided by PCDepGraph eliminate up to 90.18% of memory instructions and yield up to 2.84x kernel speedup; reuse-scope distributions remain consistent across platforms, supporting that the representation captures program structure rather than transient hardware behavior.

### [2] [SubGPU Pipelining: Intra-GPU Fine-Grained Spatial Parallelism for LLM Inference](https://arxiv.org/abs/2611.14904)

<details>
  <summary>Details</summary>
Motivation: LLM decode 由大量短小、以访存瓶颈为主的 kernel 构成（如 GEMV、LayerNorm、Attention 的 decode 形态），单核内计算与带宽利用率都低、且使用呈突发性：执行资源在 kernel 边界出现空泡，DRAM 带宽无法持续饱和。传统的"时间维"执行（逐 kernel 串行、或只做全局 micro-batch 交替）无法让不同 kernel 的访存与计算阶段相互填充，因此需要空间维度上的并发来平抑资源使用的脉冲，提高 per-GPU 吞吐与 per-user 吞吐。

Method: 核心机制：(1) 将算子图切成有序连续段(segments)；(2) 每段绑定到一个空间 stage，stage 由互不相交的 SM 池（streaming multiprocessor pool）支撑，实现 SM 空间划分与并发；(3) 微批次(microbatch)在 stage 间流水流动，形成段内/段间的重叠；(4) 通过 CUDA Green Contexts 做 SM 级隔离与配额，kernel 使用 TensorRT-LLM 实现。优化方法：将图切分、段-stage 绑定、每 stage 的 SM 分配、微批大小视作耦合问题——任一选择都会改变重叠模式、共享资源竞争（DRAM/LLC/SM issue 带宽）、cache 状态与各段执行时间——因此构建共享资源解析模拟器（对带宽、缓存、SM 资源争用建模）在结构空间与 batch size 上搜索，绘制 per-user / per-GPU 吞吐 Pareto 前沿；硅上则以单卡 B200 通过放大 micro-batch 规模来等效模拟 32 卡 B200 部署，只评估一个选定的两 stage 配置、global batch 2048。

This paper introduces SubGPU Pipelining, a fine-grained, intra-GPU spatial execution model that cuts an operator graph into ordered contiguous segments, binds those segments to spatial stages backed by disjoint streaming-multiprocessor (SM) pools, and streams microbatches through the resulting schedule. Selecting the graph cuts, segment-to-stage binding, per-stage SM allocation, and microbatch size is a coupled optimization problem: each choice changes the overlap pattern, shared-resource contention, cache state, and execution times of the others.

The analytical shared-resource simulator searches across SubGPU pipeline structures and batch sizes to map the per-user/per-GPU throughput Pareto frontier. At matched per-GPU throughput, the modeled SubGPU frontier provides up to 2.2x higher per-user throughput than temporal execution, and at matched per-user throughput it provides up to 1.9x higher per-GPU throughput. To test physical feasibility and further validate the simulation results, silicon experiments are performed, using one B200 GPU to emulate a 32-GPU B200 deployment. The experiment evaluates one selected two-stage pipeline configuration at global batch 2,048 using CUDA Green Contexts and TensorRT-LLM kernels. Results show that SubGPU Pipelining improves mean DRAM read-plus-write throughput from 71.8% to 83.6% of peak, and reduces the 36-layer decoder iteration time by 10.33%.
