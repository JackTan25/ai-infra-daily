### [2] [Supercharging Olmo-core for Efficient and Scalable MoE Training](https://arxiv.org/abs/2611.18956)
*Tianhua Tao,Akshita Bhagia,Dirk Groeneveld,Pete Walsh,Tyler Romero,Yashas Samaga,Jacob Morrison,Iz Beltagy,Taira Anderson,Noah A. Smith,Hannaneh Hajishirzi*

  <summary>Details</summary>
Motivation: MoE 只增加参数而不成比例增加 per-token 计算，但训练成本还取决于搬运字节、常驻显存和 kernel 启动次数，这些量随「总参数量」而非「激活计算量」增长。在面向 dense 模型设计的基础设施上，这种错配代价很高：论文实测早期基线即使每 token 有效工作量几乎不变，吞吐也会随存储的专家参数规模增大而下降。目标是把随参数规模增长的开销（通信、显存、同步、kernel 开销）与非随规模增长的有效计算解耦。

Method: 1) 并行架构：放弃 FSDP，改为 DDP 为基底，叠加 Expert Parallelism（EP）、Pipeline Parallelism（PP）、分布式优化器和激活重计算，使分片策略与 MoE 稀疏性对齐。2) NVSHMEM-based rowwise EP：每个 token 按路由直接写入目标专家缓冲区，消除传统 all-to-all dispatch/combine 的 permute/重排与中间缓冲。3) 同步自由 EP：路由元数据常驻 GPU 显存，避免 host 侧同步与 CPU 调度；使用 device-scheduled grouped GEMM，由 GPU 自行决定分组 GEMM 的执行。4) 紧密集成 MXFP8：同时降低计算量、激活显存与传输字节（FP8 让通信量减半）。5) Topology-agnostic checkpoint：checkpoint 与并行布局解耦，允许不同 run / 不同拓扑间改变 EP/PP 切分。6) 另提供可选 DeepEP v2 后端用于容量外推实验。

Abstract: Mixture-of-Experts (MoE) models add parameters without proportionally increasing per-token compute. However, training cost also depends on bytes moved, memory held, and kernels launched, and many of those costs follow total parameter size rather than active compute. On infrastructure built for dense models, this mismatch is costly: in early baselines, throughput fell as stored expert parameter size grew, even though the useful work per token stayed nearly fixed. To close this gap, we present a redesigned training stack in Olmo-core, built for efficient, scalable MoE training. We replace the Fully Sharded Data Parallel (FSDP) of earlier Olmo-core versions with an architecture built on Distributed Data Parallel (DDP), and add Expert Parallelism (EP), Pipeline Parallelism (PP), a distributed optimizer, and activation recompute. We propose NVSHMEM-based rowwise EP, which writes each token directly into its expert's buffer, avoiding dispatch and combine permutation overhead. We make EP fully synchronization-free by keeping routing metadata on the GPU and using device-scheduled grouped GEMMs. Closely integrated MXFP8 cuts compute, activation-memory, and transport costs, and topology-agnostic checkpoints let the parallel layout change between runs. On NVL8 B300 nodes, the stack supports training configurations from 12.9 billion to 1.2 trillion total parameters on up to 512 GPUs, reaching 858 useful-model TFLOP/s/GPU at 1.2 trillion with MXFP8 and per-layer recompute; an experimental capacity test with the optional DeepEP v2 backend reaches 2.38 trillion. We also explain each design choice and share findings for other training systems; for example, we identify a failure pattern we call Token Gerrymandering, in which the MoE router can learn to hack the load-balancing loss, and find that overlapping communication with computation can slow the overlapped kernels by more than it hides.

### [3] [NVFP4-MLA: Unified FP4 KV-Cache Storage and Attention Computation for Multi-Head Latent Attention](https://arxiv.org/abs/2611.18972)

<details>
  <summary>Details</summary>
Motivation: 长上下文推理与 agentic 负载使 KV cache 容量与 attention 计算成为前沿 LLM 服务的主导成本。MLA 已通过低秩潜变量压缩 KV，但现有 FP8 方案在存储与算力两侧仍有进一步下探空间；而直接把 MLA 的共享潜缓存降到 FP4 有两个障碍：(1) 量化误差敏感通道会严重损伤精度；(2) MLA 中两个 attention BMM 的 reduction 方向不同（一个沿 head-dim 归约、一个沿 sequence 归约），共享 latent cache 无法同时满足两者，通常需要在两个 BMM 之间做 requantization，破坏收益。

Conclusion: MLA 的 KV 压缩与计算精度的联合 FP4 化在精度上可行，关键是"敏感通道残差补偿 + 归约方向无关的二维分块"这两个算法-系统耦合决策。工程影响：KV cache 容量约 3x 的下降直接换算为更长上下文、更大 batch 和更高 prefix-cache 命中率；低精度 attention 算力提升缓解长上下文 prefill 的 TTFT 与 decode 带宽瓶颈；代理推理与分离式部署是最大受益场景。后续需关注端到端 serving 栈（如 W4A4 GEMM 支持、残差索引开销、跨硬件可移植性）的落地程度。

NVFP4-MLA co-designs the quantization algorithm with the attention kernel and the cache system. Selective residual compensation preserves model accuracy by adding NVFP4 residuals only to the quantization-sensitive channels. Two-dimensional quantization blocks make the shared latent cache compatible with the different reduction directions of the two attention batched matrix multiplications (BMMs), removing requantization between them.
