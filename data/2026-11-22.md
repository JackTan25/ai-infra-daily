### [1] [Twindex: Index Cache Offloading with Coarse-to-Fine Selection for Long-Context Sparse-Attention Serving](https://arxiv.org/abs/2611.25078)
*Yuxuan Xia,Jiakun Fan,Han Meng,Hao Mark Chen,Shenji Wan,Dongsheng Yang*

Main category: cs.DC

TL;DR: Twindex 针对稀疏注意力长上下文解码中 indexer cache 成为 HBM 新瓶颈的问题，提出"HBM 存压缩副本 + Host 存完整 indexer cache"的两级索引方案：HBM 副本做粗筛扩大候选集，模型原生 indexer 在 host 上对候选原始行做精筛取 top-k，从而实现容量与吞吐双提升且模型权重不变、可被 CUDA Graph 捕获。


<details>
  <summary>Details</summary>
Motivation: 长上下文解码的 batch 大小受 GPU HBM 容量约束。在稀疏注意力（如 DeepSeek Sparse Attention 类）模型中，每步需用 indexer 对全部历史 index entry 打分，因而 indexer cache 必须常驻且随上下文线性增长。当主 KV 已被 offload 到 host 内存后，indexer cache 反而成为每请求 HBM 占用的主导项（1M token 时 Qwen 上占 63%、V4.1 上占 75%），使 KV offload 带来的容量收益被这部分"元数据"侵蚀，HBM 容量与 top-k 选择精度之间形成矛盾。

Method: 核心是索引的分层与压缩：1）HBM 中仅保存 indexer cache 的紧凑副本，由离线一次性学习得到的"共享分量 + 压缩残差"两部分组合而成；2）每步先用该副本做低精度粗筛，输出一个更大的候选集合；3）再在 host 内存中按候选的原始行执行模型自身的 indexer 打分，选出真正的 top-k；4）主 KV 仍按 top-k 从 offload 的 host 主 KV 读取。整个流程不修改任何模型权重，且 kernel 结构对 CUDA Graph 友好。系统层面还保留了每请求独立索引，并允许 Qwen/GLM 请求在 host 内存中共享前缀主 KV。

Result: 1M token、现代 GPU 上：(1) 容量方面，相比仅做 KV offloading，Qwen、V4.1、GLM-5.2 分别可容纳 1.78×、1.62×、3.03× 的请求数；(2) 吞吐方面，在 host 内存不构成限制时，解码吞吐分别提升 1.44×、1.25×、2.54×；(3) 精度方面，评测集平均分相对 baseline 下降不超过 3.1%。

Conclusion: Twindex 揭示并解决了稀疏注意力服务中的一个新瓶颈转移问题：KV 下沉到 host 后，索引/元数据成为新的 HBM 压力点。其"粗筛-精筛"分层思想把容量问题转化为一次廉价近似检索 + 一次精确行读取，在几乎不损精度的前提下同时改善可服务 batch size 与解码吞吐，对长上下文稀疏注意力推理栈（KV offload、分层存储、索引压缩）具有直接的工程借鉴价值。

Abstract: In long-context decoding, GPU memory (HBM) caps how many requests a GPU decodes at once. Sparse-attention models such as Qwen3.8-Flash-Next, DeepSeek V4.1-Flash and GLM-5.2 add an indexer: at every step it scores all past index entries with its own indexer cache, and attention reads the main KV of only the top-k entries. We find that once serving systems move the main KV to host memory, the indexer cache becomes the HBM bottleneck, at 63% of per-request HBM on Qwen and 75% on V4.1 at 1M tokens. Therefore, we introduce Twindex, which keeps only a compact copy of the indexer cache in HBM and the full indexer cache in host memory. At each step, the copy selects a larger candidate set, and the model's own indexer picks the top-k from the original rows of the candidates in host memory. The copy combines the shared component with the compressed residuals, both learned once offline. Twindex changes no model weights and runs inside CUDA graphs. At 1M tokens on modern GPUs, Twindex fits $1.78\times$, $1.62\times$ and $3.03\times$ as many requests as KV offloading alone on Qwen, V4.1 and GLM-5.2, and reaches $1.44\times$, $1.25\times$ and $2.54\times$ decode throughput when host memory does not limit the batch. Every request keeps its own index, and Qwen and GLM requests share prefix main KV in host memory. In our evaluations, mean benchmark scores are at most 3.1% below the baseline's.

### [2] [Berth: SLO-Preserving GPU Sharing Without New Preemption](https://arxiv.org/abs/2611.25091)
*Mohammadali Khodabandehlou,Mahdi Alizadeh,Lei Gao,Murali Annavaram,Bhaskar Krishnamachari*

Main category: cs.DC

TL;DR: Berth 是一个纯用户态系统，不修改应用、框架、内核或驱动，利用商用 GPU 内置时间片抢占器的"上下文切换点"作为外部控制抓手，通过预加载 shim 控制 best-effort（如训练）任务向 GPU 提交工作的时机，从而在共享 GPU 上同时保住延迟敏感推理的 SLO 与 best-effort 吞吐。


<details>
  <summary>Details</summary>
Motivation: 推理服务按最坏负载预留 GPU，导致大量容量闲置；用 best-effort 任务（如训练）填谷是显然的解法，但延迟难以保证：空间共享无法驱逐已在运行的 kernel，时间共享只能"轮流"，硬件 MIG/分区以闲置未用资源为代价换取隔离。已有兼顾 SLO 与利用率的系统需要深入栈内（重写 kernel、打驱动补丁、埋点框架），闭源 GPU 栈的运维方无法做到。作者主张"无需深入栈内"。

Conclusion: 在闭源 GPU 栈上实现 SLO 保障的共享，不需要新的抢占机制，只需要控制既有抢占机制"看到什么"。这提示 GPU 多租户隔离的一个重要方向：把调度权从硬件/驱动层上移到用户态提交路径的控制上，以极低的部署门槛获得细粒度优先级。

Abstract: Inference services keep GPUs reserved for their worst-case load, and most of that capacity sits idle. Filling it with best-effort work such as training is the obvious remedy, and latency is why it rarely happens: on a shared GPU, a request that must finish within milliseconds finds the best-effort job's kernels running or queued ahead of it. Spatial sharing cannot evict them, temporal sharing gives the request only its turn, and hardware partitioning protects it by idling what it does not use. Systems that keep both the SLO and the utilization have reached inside the stack (rewriting kernels, patching the driver, instrumenting the framework), which the operator of a closed GPU stack cannot do. This paper argues that reaching inside is unnecessary. The time-slicer built into commodity GPUs already preempts a running kernel within a fraction of a millisecond and switches the moment a context runs out of work; what it lacks is priority, and priority can be created from outside by controlling what the best-effort context has to run. Berth changes no application, framework, kernel or driver. Across 31 scenario points with MLPerf SLOs and 13 baselines, Berth meets SLOs within a few percentage points of running alone, above every baseline, with 2.7-3.5x the best-effort throughput of the strongest ones; beside LLM serving, it meets per-token targets for nearly every request while training keeps running. Sharing a closed GPU under SLOs needs no new preemption mechanism, only control over what the existing one sees.

### [3] [TripleKV: Predict, Prefetch, Protect -- KV Cache Management for AI Agents](https://arxiv.org/abs/2611.25112)
*Shashwat Jaiswal,Chloe Alverti,Mengmei Ye,Chen Wang,Hubertus Franke,Fan Lai,Tianyin Xu,Josep Torrellas*

Main category: cs.DC

TL;DR: TripleKV 是一个针对 LLM Agent 工作负载的三级（GPU/DRAM/SSD）KV cache 管理系统，核心思想是利用 agent 的工具调用（tool execution）期间的可预测空闲窗口，做“工具感知的延迟预测 + 提前预取”，把 KV block 从 SSD 预取到 host DRAM，从而把 KV 回填从关键路径上移除。


<details>
  <summary>Details</summary>
Motivation: LLM agent 在推理与工具执行之间交替，每次调用都复用不断增长的上下文；高并发下 KV cache 工作集可达数百 GiB，远超 GPU 显存。闲置 block 被驱逐到慢速存储层后，返回的 agent 需要重新取回，造成关键路径上的 SSD 读和 TTFT 抖动。已有 DRAM/SSD 分层（如 vLLM 扩展）只是被动按需取回；而 GPU 侧预取又要占用稀缺显存并与并发推理争抢资源。

Method: 1) 三级 KV 管理：GPU 显存 / host DRAM / SSD；2) 工具感知的延迟预测器，估计每次 tool call 的完成时刻，据此提前把后续推理所需的 KV block 从 SSD 预取进 DRAM（KV 需求集合在 agent 场景下先验已知，只有复用时刻不确定）；3) 不在 GPU 上做预取，避免预留显存与干扰并发请求；4) 消除 DRAM 中与 GPU 常驻 block 的重复副本，提高 DRAM 有效容量；5) victim-cache 机制：block 被逐出 GPU 后仍可在 SSD 上按需回填，形成对 GPU 的后备层。

Result: 在 data、web、coding 三类 agent 上，需要关键路径 SSD 读的请求比例从 45–76% 降到 10% 以下；相比扩展了 DRAM+SSD KV 层的 vLLM，P95 TTFT 最多降低 49%；相比近期 agent-aware 系统，P95 TTFT 低 1.5–7×。

Conclusion: TripleKV 说明：agent 负载中“KV 复用集合已知、复用时刻不确定”这一特性可被显式建模并转化为预取机会，用便宜的 DRAM 预取替代昂贵的 GPU 预留，即可显著压低尾延迟。对服务系统的实践意义在于把 KV 分层管理与 agent 执行语义（工具调用时长）耦合起来，是一种低成本、可叠加在现有 vLLM 类引擎上的调度/存储协同优化。

Abstract: LLM agents alternate between inference and tool execution, repeatedly reusing their growing context across calls. Under high concurrency, their combined key-value (KV) cache working set can reach hundreds of GiB, far exceeding GPU memory capacity. As idle KV cache blocks are evicted to slower storage tiers, returning agents incur expensive retrievals that stall inference.
  To address this problem, we present \emph{TripleKV}, a three-tier KV cache management system that hides the delays of these retrievals. %exploits tool execution to hide these delays. In agentic workloads, the KV blocks needed by the next inference request are known in advance; only the time of their reuse is uncertain. TripleKV uses a tool-aware latency predictor to estimate when each tool call will complete and prefetches the required KV blocks from SSD into host DRAM ahead of time. Unlike GPU prefetching, this avoids reserving scarce GPU memory and interfering with concurrent inference requests. To further improve DRAM utilization, TripleKV eliminates duplication of GPU-resident blocks in DRAM, and introduces a victim-cache mechanism that refills blocks from SSD upon their eviction from GPU memory.
  Across data, web, and coding agents, TripleKV reduces the fraction of requests requiring critical-path SSD reads from 45--76\% to under 10\%. It also reduces P95 time to first token (TTFT) by up to 49\% compared with vLLM extended with DRAM and SSD KV-cache tiers, and achieves 1.5-7$\times$ lower P95 TTFT than recent agent-aware systems.

### [5] [AscMLA: Unlocking FP4 Efficiency for Long-Context MLA Decoding through Asymmetric Scaling](https://arxiv.org/abs/2611.26106)
*Zechun Zhou,Zhiyong Zheng,Xiaomin Zhang,Lin Ye,Han Li,Jingwei Sun,Guangzhong Sun,Jing Li*

Main category: cs.DC

TL;DR: AscMLA 针对 MLA（Multi-head Latent Attention）长上下文解码中 KV cache 读放大问题，提出在单一 FP4 潜变量 payload 上直接计算的非对称 K/V 分块缩放方案，配合流水化缩放因子传递，避免反量化或双份编码的开销，实现比 FP8 少 38.2% 显存、相对 TRT-LLM FP8 1.35x、相对 CAKE NVFP4 MLA kernel 1.26x 的几何平均加速。


<details>
  <summary>Details</summary>
Motivation: 长上下文解码是访存/带宽受限的，KV cache 随序列增长不断被重复读取，成为 decode 阶段的瓶颈。FP4 能把 cache 容量与流量再压缩一半，但 FP4 动态范围窄，必须依赖 block scaling（分块缩放）保证精度。问题在于 MLA 的 K 与 V 共享同一个压缩潜变量（latent），而 K（用于 QK^T 打分）与 V（用于加权求和）对缩放因子的敏感度不同：K 需要更细/更保守的量化以保证 logits 精度，V 对误差相对宽容。若共享一套 scale，会破坏其中一方精度；现有做法要么在片上反量化成高精度再计算（多一次转换，增加 ALU/寄存器压力和延迟），要么为 K/V 分别存一套编码或 scale（变相抵消 FP4 的存储收益）。论文动机即是消除这一"精度—开销"权衡。

Method: 核心是两点：(1) 非对称 K/V 缩放（asymmetric K/V scaling）——保持单一 FP4 payload（bytes 只存一份），但让 K 与 V 各自拥有独立的 block scale，在 MMA 前后通过 scale 的乘性分解把 K 侧与 V 侧的缩放差异吸收掉，从而无需 dequant 或双份编码即可直接在 FP4 上完成 MLA 的两次矩阵乘（QK^T 与 PV）；(2) 流水化 scale 传递（pipelined scale delivery）——把 scale 的加载与其对应数据块的 MMA 在时间上错开/重叠，让 scale 的读取与转换隐藏在数据搬运/计算之后，避免 scale 成为新的串行化依赖。整体工程落点是 decode 阶段的自定义 attention kernel（融合 FP4 MMA + 片上缩放应用），而非改动训练或模型结构。

Result: 相对 FP8 MLA cache 减少 38.2% 的 cache 显存占用（同时同比降低 KV 读取流量，对带宽受限的 decode 直接有利）；性能上相对 TRT-LLM 的 FP8 MLA kernel 几何平均 1.35x，相对 CAKE 的 NVFP4 MLA kernel 1.26x。注意 1.26x 的对比说明其收益不只是来自位宽（同为 4-bit），而主要来自消除了反量化/双份编码的额外执行与存储开销。

Conclusion: 该工作的系统贡献在于：识别出 MLA 中"K/V 共享潜变量"与"FP4 需 per-block scale"之间的结构性冲突，并用非对称 scale + 流水化 scale 投递把冲突在 kernel 层面化解，使得低比特 KV cache 的收益第一次可以在 MLA 上"无附加税"地拿到。工程影响主要体现在长上下文 serving：更小的 KV 占用意味着同等 HBM 下更大 batch/更长上下文，更低的读流量直接提升 decode 吞吐；但其价值高度依赖硬件是否支持 FP4 MMA 且 scale 应用能在片上高效完成（Blackwell 级 MMA/scale 通路），对缺少原生 FP4 支持的平台需软件模拟，收益会打折。此外摘要未披露精度（长上下文下的质量退化）与端到端 serving 指标（TTFT/TPOT、吞吐、并发），这是评估其可部署性时最需要补的信息。

AscMLA uses 38.2% less cache memory than FP8 and achieves geometric-mean speedups of 1.35x over TRT-LLM's FP8 and 1.26x over CAKE's NVFP4 MLA kernels.
