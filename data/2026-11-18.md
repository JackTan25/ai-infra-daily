### [1] [Collecting Infrastructure-Level Measures for Energy Analysis in Modern Computing Infrastructures](https://arxiv.org/abs/2611.22160)
*Isac Pasianotto,Stefano Cozzini,Niccolo Tosato*

Main category: cs.DC

### [2] [TAILROLL: Tail-Aware Rollout Acceleration for RL-Based LLM Post-Training](https://arxiv.org/abs/2611.22206)
*Niloofar Gholipour,Marcos Assuncao,Timothy Yu,Gursimran Singh,Rajkumar Buyya,Julien Gascon-Samson,Zhenan Fan,Yong Zhang*

Main category: cs.DC

TL;DR: TAILROLL 是一个集成在开源 RL 框架中的在线调度器，针对 LLM RL 后训练的 rollout 阶段，通过无状态在途迁移（stateless in-flight migration）与充分性门控终止（sufficiency-gated termination）两项机制，同时压缩"不均衡浪费"与"长尾拖尾浪费"，在十种配置下把 rollout 气泡比降低 21%–74%、跨引擎 KV cache 不均衡降低 44%–79%，端到端 rollout 时间减少 24%–34%，长 CoT RL 的完整 step 时间减少 21%–22%，p95 请求时延降低 28%–37%，生成吞吐最高提升 33%，且最终 reward 相当或更高。


<details>
  <summary>Details</summary>
Motivation: RL 后训练的 rollout 阶段被重尾响应分布支配：每个 step 都要等最长的响应完成，导致引擎空闲。异步训练只能"掩盖"而不能消除这种空闲。作者进一步把浪费拆成两类：imbalance waste（请求放置不均 + decode 争用引起的跨引擎负载与 KV cache 不均衡）和 straggler waste（等待最长响应）。关键观察是——决定 step 上界的往往不是平均负载而是尾部长度，因此调度目标应当是"削尾"而非"均摊均值"。

Method: 1）无状态在途迁移：在 chunk 边界把 decode 请求从一台引擎迁到另一台，迁移后仅需一次 re-prefill 即可恢复生成；迁移策略是"基于空闲度（freeness）+ 代价感知"的尾部均衡策略，把长尾请求从拥塞引擎上卸载到空闲引擎，同时把迁移代价（re-prefill 的 token 计算量）计入决策。2）充分性门控终止：当某响应对应的 GRPO group 已收集到足以估计 advantage 的样本数时，提前终止该响应，并将其部分输出在训练 loss 中 mask 掉，从而不再为统计上已无信息增益的尾部 token 付费。

Result: 十种配置下：rollout 气泡比下降 21%–74%，跨引擎 KV cache 不均衡下降 44%–79%。端到端 RL 训练：rollout 时间减少 24%–34%，长 CoT RL 的完整 step 时间减少 21%–22%，p95 请求时延降低 28%–37%，生成吞吐最高提升 33%，最终 reward 相当或更高。

Conclusion: 该工作把 RL rollout 的调度问题从"负载均衡"重新表述为"尾部均衡 + 统计充分性驱动的早停"，并在真实开源 RL 框架中落地。工程意义在于：迁移机制要求引擎支持请求级 KV cache 导出/导入与 chunk 级抢占恢复（代价是 re-prefill），这为推理引擎的 API 与调度器设计提供了明确需求；充分性门控把训练侧的 advantage 估计语义引入服务侧调度，是跨层（训练语义 × serving 调度）协同的一个可复用范式。

Abstract: RL post-training of large language models (LLMs) is bottlenecked by rollout: heavy-tailed responses leave engines idle as each step waits for the longest response. Asynchronous training masks, but does not eliminate, idle time. We distinguish imbalance waste (uneven placement and decode contention) from straggler waste (waiting for the longest response). Tail length, not average load, often sets the step bound. We propose TAILROLL, an online scheduler integrated into an open-source RL framework. It combines stateless in-flight migration and sufficiency-gated termination. Migration moves decoding requests between engines at chunk boundaries and resumes them with one re-prefill under a freeness-based, cost-aware tail-balancing policy. Termination stops a response when its GRPO group has enough completed samples for advantage estimation, masking its partial output from the training loss. Across ten configurations, TAILROLL reduces rollout bubble ratio by 21% to 74% and cross-engine KV-cache imbalance by 44% to 79%. In end-to-end RL training, it cuts rollout time by 24% to 34%, full step time by 21% to 22% on long-CoT RL, and p95 request latency by 28% to 37%, while raising generation throughput by up to 33% with comparable or higher final reward.

<details>
  <summary>Details</summary>
Motivation: 事件流中 key 分布高度不均匀（少数 dominant key 事件量高几个数量级），静态 key-based routing 会把热点集中到个别 worker，造成长尾与吞吐上限。已有 split-heavy 分区方案能改善平衡但引入巨大 key fan-out（下游需为同一 key 维护多份状态/触发 merge），且大多依赖离线统计或全局元数据服务，无法适应流式分布漂移与作业重启。CheckCo 的动机是：在无先验统计、低 fan-out、可容忍分布漂移与重启的条件下做到近似最优的负载均衡。

Method: 核心机制是"checkpoint 循环 + 动态 oracle"：(1) worker 本地维护 per-key 事件计数，仅有本地视图，无全局同步开销；(2) 每个 checkpoint barrier 时把本地计数合并成全局 per-key 频率估计，构成动态 oracle；(3) 依据估计频率为每个 key 分配 split 数（约正比于其频率），再用经典调度（如 LPT/list scheduling）把 split 打包到 worker，生成下一窗口的 partitioning function；(4) 该函数只对下一个 checkpoint 窗口生效，因此路由策略随分布变化滚动更新，且可从 checkpoint 状态恢复。理论上给出负载不平衡度的近似比界（借用经典 makespan 调度结果）以及对总 key fan-out 的界。

Shifts in the key distribution are reflected in routing from the next checkpoint on, and the load stays balanced through job restarts.
