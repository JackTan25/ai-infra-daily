### [1] [KernelOPT: Dispatch-Aware Agentic Search for GPU Kernel Optimization](https://arxiv.org/abs/2609.30059)
*Aheli Poddar,Sanskar Prasad,Arindam Samanta,Subha Chakraborty,Vishal Goyal,Rohit Singh Rathaur*

Main category: cs.DC

TL;DR: KernelOPT 是一个多代理（multi-agent）系统，将编译后的模型视为结构化产物，仅对编译器生成的 Triton 子内核做优化，保留 cuBLAS/cuDNN 等厂商库调用，并通过"四道门"验证级联（静态校验、多种子正确性、模型级 float64 回退验证、性能门控）在优化过程中过滤候选，最后端到端重缝合验证。在 KernelBench 250 题上取得相对 torch.compile 的几何平均加速：Level 1 1.40×、Level 2 1.15×、Level 3 1.07×。

Motivation: 深度学习训练/推理性能关键取决于 GPU kernel 效率。PyTorch Inductor 等现代编译器能自动从高层模型代码生成 GPU kernel，但常大幅落后于专家手写实现。已有的 LLM 辅助 kernel 优化器虽能缩小单个独立 kernel 的差距，却把编译模型当作黑盒：它们只针对孤立的 standalone kernel 优化，不尊重编译器的结构性决策，也不做端到端模型级验证——因此生成的"更快 kernel"在重新缝合回模型后可能破坏正确性或语义等价。

Method: 核心思路是把编译后的模型当成结构化制品而非黑盒。1) 边界划分：保留厂商库调用（cuBLAS、cuDNN），只把编译器生成的 Triton 子内核作为优化目标，避免与高度调优的 vendor kernel 竞争。2) 用五个 profiling 引导的 LLM agent 协同完成优化（profiling 驱动定位热点、生成候选变换）。3) 四道门验证级联在优化过程中逐层过滤候选：(a) 静态验证，(b) 多种子正确性，(c) 模型级 float64 回退（float64-fallback）验证，(d) 性能门控。4) 只有通过全部门控的候选才被采纳并重新缝合为完整模型，做端到端验证；若无候选通过，则保留编译器基线（保证不劣化）。5) 接口支持 PyTorch nn.Module、独立 Triton kernel 以及 Helion kernel。

Result: 在 KernelBench 250 道题上评估，相对 torch.compile 的几何平均加速：Level 1 为 1.40×（100 题中 51 题胜出），Level 2 为 1.15×（100 题中 31 题胜出），Level 3 为 1.07×（50 题中 12 题胜出）。加速随难度/问题复杂度上升而明显衰减。

Conclusion: 贡献在于把 LLM kernel 优化从"孤立 kernel 黑盒替换"推进到"编译产物感知 + 端到端验证"的系统范式：显式尊重编译器的结构决策与 vendor 库边界，并以多级正确性/性能门控保证重缝合模型的语义等价与不劣化。工程上更贴合真实 serving/training 栈（可作为 torch.compile 之上的 drop-in 优化层），但收益主要集中在结构较简单、编译器生成 kernel 次优空间较大的场景，Level 3 类复杂模型上的实际收益有限。

Abstract: Deep learning inference and training performance depends critically on GPU kernel efficiency. Modern compilers such as PyTorch Inductor automatically generate GPU kernels from high-level model code, but frequently underperform expert-written implementations by wide margins. Recent LLM-assisted kernel optimizers can close this gap for standalone kernels, yet treat compiled models as black boxes, generally optimizing individual standalone kernels without respecting the compiler's structural decisions or verifying the model end-to-end. We present KernelOPT, a multi-agent system that treats compiled models as structured artifacts. It preserves vendor library calls (cuBLAS, cuDNN) and exclusively targets generated Triton sub-kernels using five profiling-guided LLM agents. A four-gate verification cascade of static validation, multi-seed correctness, model-level float64-fallback verification, and performance gating filters candidates during optimization and verifies the re-stitched model end-to-end. If no candidate passes all four gates, the system preserves the compiler baseline. The system accepts PyTorch nn.Modules, standalone Triton kernels, and Helion kernels. Evaluated on 250 KernelBench problems, KernelOPT achieves geometric mean speedups over \texttt{torch.compile} of 1.40$\times$ (Level 1: 51/100), 1.15$\times$ (Level 2: 31/100), and 1.07$\times$ (Level 3: 12/50) across all problems.
