### [1] [HeteroTask: Multi-Variant Task Scheduling and Execution on Distributed Heterogeneous Clusters](https://arxiv.org/abs/2611.10055)
*Hongzheng Tian,Alok Mishra,Haocheng Xu,Dejan Milojicic,Sitao Huang*

Main category: cs.DC

TL;DR: HeteroTask 是一个面向"固定 DAG + 多任务实现变体"的跨节点 CPU-GPU 异构调度框架，将 kernel 级 profiling、基于 PEFT 的多变体性能建模、host buffer 生命周期建模与由调度驱动的 MPI 执行整合在一起，并用贝叶斯优化在线校准实测开销偏差。


<details>
  <summary>Details</summary>
Motivation: 多服务器 CPU+GPU 异构集群上，DAG 应用的调度需要同时决定三件事：每个任务用哪个实现变体（CPU 变体 or GPU 变体 or 不同 kernel 实现）、放在哪个设备上、以及数据如何在节点间/设备间搬运。离线规划能利用全局依赖信息做出更好的决策，但现有做法依赖孤立的 kernel profile，忽略了运行时开销（H2D/D2H 拷贝、启动延迟、host buffer 分配、MPI 通信等），导致离线计划与实际执行严重偏离。作者针对"重复执行的固定 DAG、独占分配的节点"这一受限但真实的场景来解决这个问题。

Method: 方法由四部分组成：(1) kernel-wise profiling：对每个任务的每个变体做细粒度 profiling，得到基础执行时间与资源特征；(2) PEFT-based multi-variant planning：用参数高效微调（PEFT）构建多变体性能预测/规划模型，把变体选择与放置统一到规划阶段；(3) host-buffer lifetime modeling：显式建模 host 侧缓冲区生命周期，把 pin memory、拷贝与复用对时间线的影响纳入计划；(4) schedule-driven MPI execution：按规划好的 schedule 直接驱动 MPI 多节点执行，避免运行时再做动态决策。此外有一个 Bayesian optimization 外循环，对上述经验性开销修正项做标定（calibration），使预测模型贴合实际运行。

Result: 在最多 6 个 8-GPU 节点上评测了 5 个基准测试和由 workflow 派生的应用。在 2 个 8-GPU 节点上，HeteroTask 相比作为对比的 StarPU 实现，端到端应用完成时间降低 19.7%–72.1%。在 Canny Edge Detection 上，开销校准使 task-window makespan 相比未校准规划降低 25.0%；若同时启用 CPU/GPU 变体选择并做校准，相比未校准的纯 GPU 执行降低 58.9%。

Conclusion: 论文的核心系统贡献是"profile → 建模 → 规划 → 标定 → 执行"的闭环：用离线全局规划替代运行时启发式，同时用贝叶斯校准弥补离线 profile 与真实执行之间的 gap。工程启示是，在多节点 CPU-GPU 异构集群上，变体选择带来的收益（约 34 个百分点，从 25.0% 到 58.9%）与开销校准带来的收益（25.0%）量级相当且可叠加，因此调度器不能只做 placement，忽略实现变体与 host buffer/通信开销会让计划在高利用率场景下迅速失真。其适用边界也明确：固定 DAG、独占节点、可重复执行的工作流（如科学计算与推理流水线），对动态 shape/动态 DAG 或共享集群的适用性需要额外的在线重规划机制。

Abstract: Heterogeneous systems that combine CPUs and GPUs across multiple servers offer substantial compute capability but complicate scheduling. For DAG-based applications with multiple task implementations, effective execution requires coordinating variant selection, device placement, and data movement. Offline planning can exploit global dependency information, yet plans derived from isolated kernel profiles may diverge from execution because of runtime overheads. A Bayesian-optimization loop calibrates empirical overhead corrections for repeated, fixed-DAG workflows on exclusively allocated nodes.
