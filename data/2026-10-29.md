### [1] [INC-MoE: Overlapping In-Network Collectives and Expert Computation for Expert-Parallel Mixture-of-Experts Inference](https://arxiv.org/abs/2610.36339)
*John Stephan,Razvan Puscasu,Xu Yong,Ding Jiutao,Guan Zixuan*

Main category: cs.DC

TL;DR: INC-MoE 将 expert-parallel MoE 层的 dispatch 与 combine 两个关键路径集合通信卸载到交换机：dispatch 用交换机侧多播实现 in-network AllGather，combine 用交换机侧归约实现 in-network ReduceScatter；并在单个 persistent kernel 内以 token band 为粒度构成 AllGather–FFN–ReduceScatter 三级流水，使两条集合通信彼此重叠、并与专家计算重叠。作为 vLLM MoE 层的 drop-in 替换，在四节点四路专家并行的 OLMoE prefill 上 TTFT 最多降低 33%、吞吐最多提升 50%，且输出一致。


<details>
  <summary>Details</summary>
Motivation: 多节点 expert-parallel MoE 服务中，dispatch（把 token 送到持有其选中专家的加速器）与 combine（把专家输出送回 token 所属 rank）都位于关键路径，在多节点部署下可主导整个 MoE 层延迟。而这两条集合通信的流量方向恰好相反（dispatch 是 fan-out/AllGather 形态，combine 是 fan-in/ReduceScatter 形态），在端点侧的 ring 实现中彼此竞争而非互补，无法利用链路双向性；同时现有实现与专家计算串行，未充分重叠。

Method: 1) 网络内计算：把 dispatch 改为交换机侧多播的 in-network AllGather，combine 改为交换机侧归约的 in-network ReduceScatter，端点主机与交换机之间采用 message 语义（而非集合语义）交互，交换机承担复制与归约。2) 通信建模：指出两条集合通信在同一链路上加载相反方向，可并发执行，理论上相较并发 ring 集合通信降低带宽受限通信时间 (N-2)/(2(N-1))，N=4 为 33%、N=8 为 43%。3) 单 persistent kernel 三阶段流水：把 token 划分为 band，在 kernel 内按角色特化 thread block（gather 下一 band、compute 当前 band、reduce 上一 band），用 device 侧同步实现通信-计算、通信-通信三级重叠，避免 kernel launch 开销与全局 barrier。4) 工程集成：作为 vLLM MoE 层的 drop-in 替换。5) 评测方法：四节点 scale-out 仿真部署，配一个专用加速器模拟 INC 交换机。

Result: 在 OLMoE prefill、四路专家并行（四节点）配置下，TTFT 最多降低 33%，吞吐最多提升 50%，相对 vLLM 默认集合通信路径；输出与基线一致（bit-level/结果匹配）。实验基于 INC 交换机的专用加速器仿真，非真实可编程交换机硬件。

Conclusion: INC-MoE 表明 MoE 服务中的 dispatch/combine 是适合在网计算的典型模式：其 fan-out/fan-in 对称性天然匹配交换机多播与归约，并通过方向互补实现通信-通信重叠。结合持久化 kernel 内的 band 级流水，可在不改变模型语义、不改动上层框架的前提下获得显著的延迟与吞吐收益。主要局限是交换机能力假设（多播组、在网归约、消息语义）依赖尚未普及的 INC 硬件，评测基于仿真；未来需在真实可编程交换机上验证、扩展至 decode 阶段与更大 EP 规模，并处理负载不均、尾延迟与容错。

Abstract: In expert-parallel mixture-of-experts (MoE) serving, dispatch moves tokens to the accelerators hosting their selected experts, and combine returns expert outputs to each token's owner. Both operations lie on the critical path and can dominate MoE layer latency in multi-node deployments. We present INC-MoE, an expert-parallel MoE layer that offloads dispatch and combine to the network switch and overlaps both collectives with each other and with expert computation. Dispatch uses in-network AllGather through switch-side multicast, while combine uses in-network ReduceScatter through switch-side reduction. Both collectives use message semantics between the end hosts and the switch. Because the in-network collectives load opposite directions of each link, executing them concurrently reduces bandwidth-bound communication time by $(N-2)/(2(N-1))$ relative to concurrent ring-based collectives: 33% for four ranks and 43% for eight.
  INC-MoE partitions tokens into bands and processes them through a three-stage AllGather-feed-forward network (FFN)-ReduceScatter pipeline inside a single persistent kernel. At steady state, role-specialized thread blocks gather the next band, compute the current band, and reduce the previous band concurrently, overlapping both collectives with each other and with computation using device-side synchronization. INC-MoE integrates as a drop-in replacement for the MoE layer of vLLM. We evaluate it in an emulated four-node scale-out deployment with a dedicated accelerator emulating an in-network computing (INC) switch. On OLMoE prefill with four-way expert parallelism, INC-MoE reduces time to first token (TTFT) by up to 33% and increases throughput by up to 50% relative to vLLM's default collective path, while matching its outputs.

<details>
  <summary>Details</summary>

Method: 关键洞见是改变每个组件模型要预测的目标：不预测精确值，而是为每个组件学习简单、可解释的界，保证包含所有已观测行为，同时足够紧以支撑有意义的端到端结论。AGAR 将这些组件级界进行组合（composition），对端到端 SLO 可行性做出保守但可行动的判定；在此基础上把自动扩缩容形式化为反事实查询——"满足该 SLO 的最小资源分配是多少"。相比精确值预测，界的形式使组合误差不会失控（界可沿调用链安全传播），把"误差累积"从正确性问题降级为"保守性/紧致性"问题。

Conclusion: 论文的系统贡献在于提出"学习紧界而非精确值 + 组件界组合"的反事实性能建模抽象，并把扩缩容、成本规划、启动时间优化与性能 bug 定位统一为同一套端到端反事实查询，避免端到端学习的组合爆炸与组合式预测的误差累积。工程影响上，它提示运维/调度栈应显式建模"保守但紧"的组件级界并沿调用链传播，从而为资源分配决策提供可解释、可验证的保证；不过界方法的收益依赖界紧致度与观测覆盖，在分布漂移或高维交互强耦合场景下的紧致性与泛化仍需进一步验证。

End-to-end models must learn behavior over a combinatorial space of conditions, but composing per-component predictors causes prediction errors to accumulate. We address this challenge by changing what each component model must predict. Rather than predicting exact values, we learn simple, interpretable bounds that contain every observed behavior while remaining tight enough to support useful end-to-end conclusions. This allows us to formulate autoscaling as a counterfactual query: what is the smallest resource allocation under which an SLO is met? Our evaluation demonstrates that across three microservice applications, AGAR's bounds are actionable: its derived autoscaler reduces CPU allocation by up to 36.8% over state-of-the-art horizontal autoscalers while satisfying application SLOs.
