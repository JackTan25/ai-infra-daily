### [2] [SlackSwap: Bandwidth-Aware Activation Swapping and Recomputation for Memory-Efficient DNN Training](https://arxiv.org/abs/2610.13003)
*Hui Feng,Xun Zhou,Yuxin Wang*

Main category: cs.DC

TL;DR: SlackSwap 将主机链路时间视为显式资源预算，通过单次 profiled iteration 决定哪些激活被 offload、哪些被重算，并用 FIFO 卸载 + EDF 预取的无 barrier 调度恢复被重算/卸载挤占的吞吐，在 A100 上以一半激活内存保留 96-100% 无限内存吞吐。


<details>
  <summary>Details</summary>
Motivation: 激活 swap 的经典前提是"计算吞吐与主机链路带宽大致匹配"（2015 Titan X 上 PCIe 足以在 forward 阶段旁路 VGG-16 全部激活）。该平衡已被打破：Titan X→H100 峰值训练吞吐提升 141x，主机链路带宽只提升 3.9x。在 A100 上，主机链路仅能掩盖所研究 transformer 模型 11-38% 激活的传输。现有方案各有缺陷：vDNN/SuperNeurons/SwapAdvisor 按内存需求而非链路时间预算来卸载，产生 transfer-induced stall；block checkpointing 则相反，让主机链路闲置。核心问题是主机链路带宽已成为更稀缺的资源，需要按"时间预算"而非"字节预算"来分配。

Method: 将 host-link time 建模为显式 budget。仅需一次 profiled iteration，即得到各 layer 的重算代价与链路时间画像。据此：(1) 把 forward 阶段的链路预算优先分配给"重算代价最高"的张量（即 offload 优先，因为重算昂贵）；(2) 用剩余内存缺口驱动对"重算代价最低"张量的重算（recompute 作为内存缺口的兜底手段）；(3) 调度上采用 FIFO offload + earliest-deadline-first (EDF) prefetch，且不插入 per-layer 同步 barrier，从而让传输与计算流水重叠、避免 barrier 造成的链路空转。规划阶段不依赖迭代式搜索，是一次性贪心/优先级分配。

Result: 在 A100 上对 BERT-Large、GPT-2 XL 和 Llama-7B 风格模型做 trace-driven 仿真：SlackSwap 在使用一半激活内存的情况下保留 96-100% 的无限内存 GPU 吞吐，吞吐为最优 baseline 的 1.10-1.11x。其规划质量与对 6,600-14,000 个候选方案做遗传搜索的结果差距在 0.5% 以内，而规划生成耗时不到 0.4 秒。

Conclusion: 贡献在于把 activation offloading 从"容量问题"重新表述为"链路时间预算下的资源分配问题"，用一次剖析 + 优先级式分配取代按需卸载与逐层同步，从而在 bandwidth-bound 时代把主机链路这一真正瓶颈用满。工程含义：0.4 秒级的规划开销使其可作为运行时/编译期的一次性 pass 集成进训练栈；对 memory-bound 的大模型长序列训练，能在不牺牲吞吐的前提下降低显存占用、提高 batch size 或序列长度，并减少对重算（额外算力）与 block checkpointing 的依赖。局限：结果基于 trace-driven 仿真而非真实端到端训练，需验证在真实通信争用、多卡/多流与重叠调度下的收益；EDF 预取的正确性依赖对张量消费点的精确预测。

Abstract: Swapping saved activations to host memory once enabled GPUs to train models that exceeded their device-memory capacity when compute throughput and host-link bandwidth were roughly balanced. For example, on a 2015 Titan X, PCIe bandwidth was sufficient to offload all VGG-16 activations during the forward pass. This balance no longer holds. From the Titan X to the H100, peak training throughput increased by 141x, whereas host-link bandwidth improved by only 3.9x. On an A100, the host link can hide transfers for only 11-38% of the activations in the transformer models we study. Existing swapping approaches, such as vDNN, SuperNeurons, and SwapAdvisor, offload tensors according to memory requirements without explicitly respecting the available link-time budget, resulting in transfer-induced stalls; block checkpointing, in contrast, leaves the host link underutilized. We present SlackSwap, which treats host-link time as an explicit resource budget. Using a single profiled iteration, SlackSwap allocates the forward-pass link budget to tensors that are most expensive to recompute, resolves the remaining memory deficit by recomputing the least expensive tensors, and schedules FIFO offloads and earliest-deadline-first prefetches without per-layer synchronization barriers. In trace-driven simulations of BERT-Large, GPT-2 XL, and a Llama-7B-style model on an A100, SlackSwap retains 96-100% of unlimited-memory GPU throughput while using half the activation memory, achieving 1.10-1.11x the throughput of the best baseline. Its plans are within 0.5% of a genetic search over 6,600-14,000 candidate plans, while requiring less than 0.4 seconds to generate.

### [3] [Taking Tokenization off the Host for Agentic LLM Serving](https://arxiv.org/abs/2610.13325)

<details>
  <summary>Details</summary>
Motivation: Agentic 负载反复重发几乎不变的长上下文：前缀缓存已能跳过大部分 prefill，但每个请求仍需先被完整分tokenize才能查询/命中缓存。于是 CPU 分词这一长期被视作可忽略的阶段，变成了 TTFT 的最大组成。更严重的是前端容量问题：单个前端为整支 GPU 集群做分词，其 CPU 吞吐直接决定可喂给多少 GPU，前端成为集群级扩展瓶颈，且其 tail latency 会拖垮整体 SLA。

Method: 将整个编码流水线（预分词、BPE 合并、token-ID 组装）捕获为一张可重放的 CUDA Graph，在 GPU 上以单一 graph 执行完成编码，避免 CPU 侧逐层调度与多次 kernel launch 开销。设计上包含：短输入的判别式分流，把小请求交回 CPU 引擎（GPU 在此无收益，且能回收 CPU 在低延迟小负载上的优势）；与 vLLM、NVIDIA Dynamo 的未修改集成，作用于 tokenizer 接口层；位级精确复现参考 tokenizer，包括 GPT-2、Llama 3、Qwen 2.5、DeepSeek-V3、Gemma 3。

Conclusion: 论文把分词从"被忽略的 CPU 预处理"重新定性为 agentic 长上下文推理的系统级瓶颈，并用 CUDA Graph 化的 GPU tokenizer 给出位级兼容的工程解法。核心贡献是前端容量（GPU 供给比）与 tail latency 的大幅改善，而非单纯单请求加速；对生产栈的直接含义是：在长上下文、高复用前缀、严格 P99 的服务场景下，可用更少前端支撑更大 GPU 集群，且无需改动 vLLM/Dynamo。后续值得关注的风险点包括极短输入时的分流开销、不规则/超长 chunk 下 graph 的形状泛化、以及多前端部署下的 GPU 资源争用与显存占用对推理本身的影响。

Abstract: Agentic workloads resend long contexts that barely change between calls. Prefix caching now skips most of their prefill, yet every request must still be tokenized in full before the cache can even be consulted. Tokenization, a CPU stage long treated as negligible, becomes the largest part of time-to-first-token (TTFT), and a frontend that tokenizes for a whole GPU fleet limits how many GPUs it can feed. We present GraphTok, a GPU tokenizer that runs the entire encoding pipeline, from pre-tokenization through byte-pair encoding (BPE) merging to token-ID assembly, as one replayable CUDA graph. GraphTok reproduces the reference token IDs bit-for-bit on GPT-2, Llama 3, Qwen 2.5, DeepSeek-V3, and Gemma 3, hands short inputs to a CPU engine where the GPU cannot win, and plugs into unmodified vLLM and NVIDIA Dynamo. GraphTok encodes one million GPT-2 tokens in 1.7-3.2 ms including data transfers, and on Llama 3 it is 4.7-6.0x faster than gigatoken, the strongest CPU tokenizer. On TokTier's own single-request benchmark, it is 2.6-3.9x faster than gigatoken and up to 18.1x faster than TokTier. In vLLM with a cached prefix, it lowers mean TTFT by 2.1-2.4x. The largest gain is capacity. Across 121k to one million tokens, this is 1.75-2.5x the load gigatoken sustains, with a P99 up to 64x lower where gigatoken's tail breaks.
